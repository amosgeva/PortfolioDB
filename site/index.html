PortfolioDB
What it does Quick start Limitations GitHub

Your portfolio ledger. Your database. Nobody else's server.

An append-only ledger on Postgres, self-hosted in Docker. Every buy and sell is a row you can read; open quantity, cost basis and realized P&L are recomputed from those rows every time you look — never stored, never drifted. No accounts, no telemetry, no broker credentials. 

$ mkdir portfoliodb && cd portfoliodb
$ curl -fsSLO https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/docker-compose.yml
$ curl -fsSLO https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/Makefile
$ curl -fsSL  https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/.env.template -o .env
$ make init && make up && make schema

That is the whole install — there is nothing to sign up for. make init generates your Postgres password and MCP token; the application image is pulled, not built, so no Python and no toolchain land on your machine. Then open localhost:8501.

Your spreadsheet wins on trust and loses on arithmetic

Most portfolio trackers want your brokerage login, keep your positions on their servers, and show you a return figure that is really whatever their integration last managed to sync. So the trustworthy option ends up being the one that cannot do the maths — a spreadsheet where you type everything and reconcile by hand. PortfolioDB does not connect to your broker at all. You enter trades, or import a CSV, into a Postgres database that exists only on your infrastructure, and every number on screen is recomputed from that ledger on the spot.

What it actually does

Four things worth knowing before you install it.

The ledger

Lots, not positions

Every BUY and SELL is a row. Open quantity, cost basis and realized P&L are recomputed from lots on every read, never stored — so no number can quietly drift from the trades behind it. FIFO and moving-average engines run side by side over the same rows.

Ask your own agent

An optional MCP server exposes 47 tools, 7 resources and 7 prompts over the same engines the dashboard uses — positions, P&L, concentration, correlation, data quality, a pre-trade "what if". Trust

Numbers you can audit

Splits are applied at read time from corporate_actions, so an adjustment is undone by deleting a row. A Data Health page answers "can I trust this number, and if not why" per symbol — judged against the collector's own runs rather than a clock, because a weekend gap is legitimately 64 hours.

Quick start, in full

You need Docker with Compose. Nothing else: the image is pulled, not built, so there is no Python, no toolchain and no compile step on your machine.

  1. Make a directory and fetch three files — docker-compose.yml, .env.template (saved as .env) and the Makefile.
  2. make init — generates the Postgres password, writes it to the two keys that must match, generates an MCP token, and tightens permissions on .env. Safe to re-run; it never rotates a secret you already have.
  3. make up — starts Postgres, the dashboard and the price collector.
  4. make schema — creates the tables and applies migrations in order.
  5. make demo-seed — optional fictional data, so the dashboard has something to show before you type in a single trade.
  6. Open http://localhost:8501, then set your timezone and collector window under Manage → Settings. The defaults are UTC-shaped.
$ mkdir portfoliodb && cd portfoliodb
$ curl -fsSLO https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/docker-compose.yml
$ curl -fsSLO https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/Makefile
$ curl -fsSL  https://raw.githubusercontent.com/amosgeva/PortfolioDB/main/.env.template -o .env
$ make init
$ make up && make schema
$ make demo-seed        # optional, fictional data

Prefer not to trust a Makefile you have not read? Every target is a one-line docker compose command, and the README lists them. Pin a version instead of tracking latest with PORTFOLIODB_IMAGE=ghcr.io/amosgeva/portfoliodb:1.0.0 in .env.

What it does not do

These are design decisions, not gaps waiting to be filled. Read them before you install rather than after — if one of them rules you out, better to find out now.

✕

One currency, end to end. If you hold instruments in several, the totals are arithmetic on mixed units — wrong, not approximate.

✕

No authentication. Single-user by design; the network is your access control. Do not put it on the open internet — do put it behind your own VPN, tailnet or LAN. Exposing it safely →

✕

No broker sync. You enter trades or import a CSV, because syncing would mean holding your credentials. If your history is long this costs you an evening — the CSV import guide is the shortcut.

✕

Equities and ETFs only. No options, no bonds, no crypto-native accounting, no shorts. Cash balances are entered by hand.

✕

One person's portfolio. No multi-user, no sharing, no roles.

Not investment advice

This is a record-keeping and analysis tool. It reports what your ledger says and, if you enable the advisor, what a language model thinks about it — neither is financial advice.
